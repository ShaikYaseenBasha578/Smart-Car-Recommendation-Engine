Knowledge base

Write the staged changes in one transaction, after a backup.

If anything fails halfway the transaction rolls back, and the backup makes the last good state recoverable.

  1. Check that no other process holds the database file.
  2. Record the file hash.
  3. Take a backup.
  4. Write all changes in one transaction.
  5. Run the database integrity check.
  6. Compare the result table by table with the staging copy.

Rows are never deleted. A model or variant that is no longer listed is only flagged for review. The latest run's result matched its staging copy exactly.

What it refuses to do

Four rules the pipeline will not bend.

It never fabricates

One source alone decides nothing. If only one site states a value and no brochure does, the cell stays blank and the reason is listed.

It never deletes rows

Rows are added or amended. A car that disappears from a listing is flagged for a human, not removed.

It never writes without a backup and gates

Every write follows the sequence above: staging copy, four gates, an identical re-run that changes nothing, backup, then one transaction.

It never works around a site block

When a site refuses a request, the pipeline records the block and moves on. It does not disguise itself or retry around it.

The three evidence layers

Specifications, professional opinion and owner opinion are kept apart and checked differently.
